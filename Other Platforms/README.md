# 🔍 Problem-Solving Methodology

My general approach to solving DSA problems follows this process:

```text
Understand the Problem
        ↓
Analyze the Constraints
        ↓
Identify Key Observations
        ↓
Recognize Possible Patterns
        ↓
Choose Appropriate Data Structures
        ↓
Design the Algorithm
        ↓
Implement the Solution
        ↓
Test Edge Cases
        ↓
Analyze Time & Space Complexity
        ↓
Optimize When Possible
```

This methodology helps develop systematic problem-solving skills and encourages efficient solutions rather than relying only on memorized approaches.

```text

│

    │
    ├── README.md
    │
    └── Platform/

        │
```

Whenever I begin solving problems on a new platform, it can be added as a dedicated folder inside `Other Platforms`.

Each platform can maintain its own:

* Platform profile
* Platform information
* GitHub Platform link
* Problem collection
* Solution documentation
* Problem sources

This allows new platforms to be added without modifying this main README.

# 🌐 Platform vs GitHub

This repository maintains a clear distinction between the original coding platform and the GitHub documentation of the solutions.

|                           | Original Platform                           | GitHub                               |
| ------------------------- | ------------------------------------------- | ------------------------------------ |
| **Purpose**               | Problem solving and submissions             | Solution documentation and portfolio |
| **Profile**               | Personal account on the respective platform | Repository section                   |
| **Statistics**            | Maintained by the respective platform       | Not duplicated here                  |
| **Submissions**           | Recorded by the respective platform         | Solutions documented here            |
| **Scores / Achievements** | Maintained by the respective platform       | Not duplicated here                  |
| **Solutions**             | Submitted to the respective platform        | Organized and documented in GitHub   |

### In short:

**Original Platform → Actual platform activity**

**GitHub → Documented solution portfolio**

This avoids duplicating dynamic platform information inside the repository.
